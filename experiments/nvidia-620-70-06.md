# Controlled NVIDIA 620.70.06 experiment (RTX 5080 / Xid 109)

This experiment is **separate from production Helix configuration**. It uses
exactly the existing `nixpkgs.json` pin, kernel and gaming profile; only the
NVIDIA driver version and a human-readable boot label change. Do **not** bump
Nixpkgs, change Proton, add launch options, or switch from the NVIDIA open
kernel modules in the first test pass.

The test exists to compare the known-bad **595.71.05** baseline against
**620.70.06** for Space Marine 2 (Steam 2183900) and STAR WARS: Galactic
Racer (4078430). Other games (Cyberpunk 2077, Tekken 8) are regression
controls. See [`docs/xid109.md`](../docs/xid109.md) for the case file and
previous unsuccessful mitigations.

## Workflow on Helix

Use the isolated experiment branch. Do not merge the branch into `main` to
perform this test, and do not run `helix-update` during the experiment (it is
intentionally scoped to `main`). The commands below must run from the repo:

```bash
cd ~/Projects/nixos-helix
bash ./scripts/helix-nvidia620-test.sh prepare
bash ./scripts/helix-nvidia620-test.sh build
bash ./scripts/helix-nvidia620-test.sh stage
bash ./scripts/helix-nvidia620-test.sh status
```

1. **prepare** prefetches the official 620.70.06 NVIDIA x86_64 driver and
   matching open-module, settings and persistence-daemon source archives,
   calculating Nix content hashes instead of using guessed values. It writes
   a one-off top-level NixOS configuration under
   `~/.local/state/helix/nvidia-620.70.06/configuration.nix`. It changes no
   live system settings.
2. **build** builds a new complete NixOS closure with the repo's pinned
   Nixpkgs, with a private `candidate` result link. It does not register the
   system or touch the boot loader. Inspect `nvd diff` if available.
3. **stage** captures the original system closure as a persistent Nix GC root,
   then runs `nixos-rebuild boot` against the prepared config. This adds a
   **separate actual system generation**, labeled `helix-nvidia620-test`, and
   makes it the default for the **next** boot. The currently running GPU
   driver remains untouched.
4. **status** prints the baseline closure, candidate, live driver, generation
   list and recent NVIDIA Xids.

The `prepare` step downloads approximately 550 MB for the NVIDIA installer,
plus source archives. Builds can require local compilation; a build failure
means **no generation has been staged**. Do not proceed to `stage` unless the
full system build succeeds. The script refuses to stage a second time while a
baseline is recorded, and refuses build/stage if the repo revision differs
from the one recorded by `prepare`.

After staging, inspect the listed new generation and `sudo reboot`. Helix uses
systemd-boot and retains prior NixOS generations in its boot menu (5-second
menu timeout). If graphics fail, choose the previous known-good NixOS entry
instead. The test boot entry should be identifiable as `helix-nvidia620-test`.

## Acceptance / failure evidence

After reboot:

```bash
nixos-version
nvidia-smi --query-gpu=name,driver_version --format=csv,noheader
bash ./scripts/helix-nvidia620-test.sh status
```

Require the boot label and installed GPU driver to say `helix-nvidia620-test`
and `620.70.06`. If they do not, **stop**: don't call the result a driver test.
Use the same Steam compatibility tools and launch options as the baseline
without adding `VKD3D_CONFIG=descriptor_heap` yet. Run Galactic Racer and
Space Marine 2 in their previously failing sequences, separately. For each,
record minutes to first failure, whether the screen clears with audio still
playing, and whether `Xid 109` appears in the kernel journal. Run Cyberpunk
2077 and Tekken 8 as controls.

Inspect kernel errors after each game:

```bash
sudo journalctl -k -b --no-pager | grep -Ei 'Xid|CTX SWITCH TIMEOUT|NVRM'
```

**Pass:** both previously failing workloads remain usable in sustained
comparable gameplay and no new Xid 109 occurs. A single successful short run
is *promising*, not proof of a permanent fix. **Fail:** the same visual hang
and Xid 109 recur. If the driver alone fails, a separate second-pass test with
`VKD3D_CONFIG=descriptor_heap %command%` is reasonable; log it as a distinct
variable, not part of the initial driver-only A/B experiment.

## Rollback

While the test system is still running, or after booting the prior system from
the systemd-boot menu:

```bash
cd ~/Projects/nixos-helix
bash ./scripts/helix-nvidia620-test.sh rollback
sudo reboot
nvidia-smi --query-gpu=name,driver_version --format=csv,noheader
```

`rollback` selects the preserved baseline **for the next boot only**; it does
not hot-switch loaded kernel modules or the graphical session. The baseline
store path and GC root remain in the test state directory for audit/recovery.
Do not manually delete the GC root until the test is concluded and the
baseline is safely available as a standard generation. If you cannot reach a
terminal in the test generation, select a previous NixOS boot entry; the
script can then restore the recorded baseline as the default.

Keep the findings and timestamps in [`docs/xid109.md`](../docs/xid109.md),
including negative results and the exact test generation. Only consider
updating production `hardware/nvidia.nix` after reviewing those findings.
